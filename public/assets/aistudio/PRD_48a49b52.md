# Elli – Product Requirements Document (PRD)

**Version**: 1.0 (Production-Ready)  
**Product**: Elli – Personal Desktop AI Assistant  
**UI Reference**: https://ellie-ai.ai.studio/  
**Last Updated**: 2026-11-10

---

## 1. Vision

Elli is a local-first, voice-enabled personal desktop AI assistant that safely orchestrates files, system commands, web fetching, and multi-step workflows on the user’s machine. It prioritizes human-in-the-loop safety (Gatekeeper), hybrid local/cloud reasoning, soft-delete recovery, and zero-cloud-latency for core actions.

## 2. Problem Statement

Most AI assistants either:
- Live only in the browser/cloud and cannot touch local files safely, or
- Run locally but lack proper confirmation, sandboxing, undo, and clear error recovery.

Users need an assistant that can create files, fetch information, summarize documents, and run system tasks while remaining transparent, reversible, and under user control.

## 3. Goals

- Allow natural language (voice or text) control of local desktop tasks.
- Enforce human confirmation before any write, delete, or system action.
- Support compound multi-step workflows (e.g., “fetch quotes from Google and save to today_quotes.txt”).
- Provide hybrid local + cloud reasoning with clear offline fallback.
- Offer soft-delete + one-click restore.
- Deliver a modern, clean desktop UI matching the System Dashboard style at ellie-ai.ai.studio.
- Export a complete, runnable Python codebase.

## 4. Non-Goals (v1)

- Multi-user collaboration or cloud sync of personal data (beyond optional backups).
- Full autonomous agent that acts without any confirmation.
- Mobile or web-only version.
- Training or fine-tuning of foundation models.

## 5. Target Users

- Developers and power users who want a local AI sidekick.
- Knowledge workers who manage files, notes, and research.
- Anyone who wants voice control + safety over local automation.

## 6. Core User Stories

1. As a user, I can speak or type “create a file named today_quotes and fetch inspirational quotes into it” and Elli will show me a preview before writing.
2. As a user, I can deny or edit any proposed action.
3. As a user, I can undo the last file action with one click (soft-delete to trash).
4. As a user, I can run common commands (create/update/delete file, fetch, summarize) from a quick command palette.
5. As a user, I can see system health (CPU, memory, disk, LLM latency) on the dashboard.
6. As a user, I can continue working offline with local model fallback.
7. As a user, I can view history of all actions and restore previous states.

## 7. Key Features (Priority Order)

### P0 – Must Have
- Floating / dashboard Prompt Runner (text + voice)
- Hybrid MCP Router (local + cloud)
- Gatekeeper intercept (Yes / No / Edit)
- Sandboxed filesystem tools
- Soft-delete + Restore
- Structured logging + basic recovery
- System Dashboard UI (metrics, active workflows, command list)

### P1 – Should Have
- Progressive trust (“Remember this action”)
- Simple memory retrieval + user preferences
- TTS two-way feedback
- One-click project export
- Authentication (local user + optional JWT for remote features)

### P2 – Nice to Have
- Full workbench phase navigator
- Advanced RLHF feedback collection
- System tray background mode
- Scheduled workflows

## 8. Success Metrics

- Time from install to first successful compound action < 10 minutes.
- % of destructive actions that go through Gatekeeper = 100%.
- User can restore any soft-deleted file in < 2 clicks.
- Core loop remains usable offline.
- Crash recovery succeeds on > 95% of simulated failures.

## 9. UI / UX Principles (from ellie-ai.ai.studio)

- Clean modern dashboard with left sidebar navigation.
- Prominent Prompt Runner with quick suggestions.
- Live system metrics cards.
- Command list with clear icons and descriptions.
- Active workflows status.
- Soft blue/purple gradient accents, high contrast, glass-style cards.
- Always show status (Ready, Running, Error) with timestamps.

## 10. Constraints & Assumptions

- Primary runtime: Python 3.11+ on Windows / macOS / Linux.
- Local models via Ollama or llama.cpp preferred.
- Cloud model (Gemini / OpenAI-compatible) optional.
- All file operations confined to `./agent_workspace/` and `.agent_trash/`.
- No automatic internet writes without user confirmation.

## 11. Open Questions

- Exact local model recommendation for good quality/speed balance.
- Whether progressive trust is enabled by default or opt-in.
- Long-term storage strategy for very large action histories.
